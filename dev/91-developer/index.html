Developer documentation

See the Contributing guidelines for proposing changes. Run the commands below from the repository root with Julia 1.12 or newer. The root project, tests and documentation share a Julia workspace and manifest.

Local setup

Fork and clone the repository, then add the original as upstream:

git remote add upstream https://github.com/dnadlinger/Levels.jl
julia --project=. -e 'using Pkg; Pkg.instantiate()'

Maintainers working directly in the repository can use origin wherever this guide says upstream.

Tests

Run the suite used by CI:

julia --project=. -e 'using Pkg; Pkg.test()'

Test items can be selected by name or tag. Pass the repository root to run_tests so TestItemRunner finds the package project:

julia --project=test -e 'using TestItemRunner; TestItemRunner.run_tests("."; filter=ti->:fast in ti.tags, verbose=true)'
julia --project=test -e 'using TestItemRunner; TestItemRunner.run_tests("."; filter=ti->occursin("Spectro", ti.name), verbose=true)'

Formatting and linting

Use an EditorConfig plugin in your editor. Wrap Markdown prose at 88 columns; .editorconfig records this preference and markdownlint checks it. Code blocks, tables and standalone links are exempt. Install pre-commit, then enable the hook and run the checks:

pre-commit install
pre-commit run -a

The hook runs the configured checks before each commit. JuliaFormatter's version is pinned in .pre-commit-config.yaml; use that version for manual formatting too, since line-breaking rules can differ between versions.

CI also checks links with lychee. With lychee installed, run:

lychee --no-progress --config lychee.toml .

Branches and pull requests

Start a branch from the current upstream master:

git fetch upstream
git switch master
git merge --ff-only upstream/master
git switch -c 42-add-answer-universe

Use the issue number and a short imperative description for the branch name. For small changes without an issue, use a descriptive prefix such as typo or hotfix; discuss larger changes in an issue first.

Keep commits focused, with informative titles in imperative or present tense. Explain breaking changes in the commit body. Before opening a pull request, run tests and pre-commit, and rebase onto any new upstream changes:

git fetch upstream
git rebase upstream/master
git push -u origin HEAD

Building the documentation

Build once, or run a live preview:

julia --project=docs docs/make.jl
julia --project=docs docs/serve.jl

The workspace already points at the local package; no separate Pkg.develop step is needed. The pages under "Examples" are rendered from the Literate.jl scripts in examples/. Repository scaffolding comes from BestieTemplate/Copier; copier update may overwrite changes to generated files.

Literature references

Literature is cited through DocumenterCitations.jl in its :alpha style. Every cited work has an entry in docs/src/refs.bib, and the Bibliography page lists all of them. To cite a new work:

  1. Add a BibTeX entry to docs/src/refs.bib, sorted by key. Keys are AuthorYear, with an a/b suffix for clashes and an established name, such as AME2020 or CODATA2022, for standard compilations. Give the complete author list, as the alpha labels and "et al." are generated from it, as well as the DOI. Enter arXiv preprints as @misc with eprint and archiveprefix = {arXiv}. Plain Unicode in titles, such as ⁴³Ca⁺, renders as is.

  2. In docstrings, Markdown pages and the example scripts, cite the key in link syntax:

    MarkdownRendered as
    [Benhelm2007](@cite)[BKR+07a]
    [Benhelm2007; Eq. (3)](@cite)[BKR+07a, Eq. (3)]
    [Arbes1994, Benhelm2007](@cite)[ABG+94, BKR+07a]
    [Benhelm2007](@citet)Benhelm et al. [BKR+07a]

    Use @citet where the authors are part of the sentence ("as discussed by …"). Put equation, section and table numbers in the citation, after a semicolon.

  3. In code comments, such as those giving the source of each value in src/species_data.jl, write the bare key, [Benhelm2007]. These keys must also be in refs.bib, which serves as the reference list for the comments.

The documentation build fails on a key that is missing from refs.bib. The REPL help shows citations by key only; the Bibliography page resolves them.

Releases

  1. Create a release-x.y.z branch and update version in Project.toml.
  2. In CHANGELOG.md, rename Unreleased to [x.y.z] - yyyy-mm-dd, add a new Unreleased section, and update the comparison links at the bottom.
  3. Commit as Release vx.y.z, open a pull request, and merge after checks pass.
  4. Comment @JuliaRegistrator register on the merged commit and follow the registry pull request returned by the bot.
  5. After registration, check that TagBot creates the tag and release, then verify the documentation workflow and the version shown in the stable docs.
